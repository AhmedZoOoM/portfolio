# UI/UX best practices applied to the portfolio (issue #39)

Researched on 2026-09-24 for a creative portfolio: a video editor presenting work to producers, agencies, and collaborators. Many of them look at it on large, high-resolution editing and design monitors. Every practice below links to its source and names the change that implements it, or the existing behavior that already complies.

| # | Practice | Source | How the portfolio applies it |
| --- | --- | --- | --- |
| 1 | Put the name and role above the fold, with no scrolling needed. | [Muzli, UX portfolio checklist 2026](https://muz.li/blog/how-to-build-a-ux-portfolio-that-actually-gets-you-hired-2026/); [NN/g, Scrolling and Attention](https://www.nngroup.com/articles/scrolling-and-attention/) | A new identity band opens the hero with **Ahmed Azzam**, **Senior Video Editor**, and **Portfolio**. It is visible on every tested viewport, from 390×844 to 3840×2160. |
| 2 | Build a clear visual hierarchy with scale and contrast, and make the most important element the largest. | [NN/g, Visual Hierarchy in UX](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/) | The name is the largest type on the page. The tagline comes next, then supporting copy. Muted mono eyebrows sit at the lowest level. |
| 3 | Remove dead space and false floors, and let the next section show above the fold as a cue to scroll. | [NN/g, Scrolling and Attention](https://www.nngroup.com/articles/scrolling-and-attention/) | The fixed-height hero and its empty band under the nav are gone. Hero padding is fluid, and the timeline row now peeks in above the fold on laptop and larger screens. |
| 4 | Keep primary navigation visible on desktop, with no hamburger. | [NN/g, Menu-Design Checklist](https://www.nngroup.com/articles/menu-design/) | This was already the case. All four links stay visible at every width, including 320 px phones, where padding tightens so none of them scroll out of view. |
| 5 | Make menu links easy to find: high-contrast text and a strong enough visual weight. | [NN/g, Menu-Design Checklist](https://www.nngroup.com/articles/menu-design/) | Nav links are larger (1.0625 rem, weight 650) and use full-strength `--text` instead of body weight. They sit in a bordered panel group, with a filled accent hover state. |
| 6 | Show the current location in the menu. | [NN/g, Menu-Design Checklist](https://www.nngroup.com/articles/menu-design/); [NN/g heuristic #1, Visibility of system status](https://www.nngroup.com/articles/ten-usability-heuristics/) | The new `nav-spy.js` sets `aria-current="true"` on the link for the section in view, which gets an accent color, a fill, and an underline. |
| 7 | Use a sticky menu on long pages, and make sure it never hides the focused element. | [NN/g, Menu-Design Checklist](https://www.nngroup.com/articles/menu-design/); [WCAG 2.2 SC 2.4.11 Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) | The header stays sticky. `scroll-padding-top` on `html` keeps anchor targets and focused elements clear of the header, alongside the existing mobile `scroll-margin-top`. |
| 8 | Keep one primary call to action per view, with secondary actions visually subordinate. | [Muzli 2026](https://muz.li/blog/how-to-build-a-ux-portfolio-that-actually-gets-you-hired-2026/); [Pixpa, hero-section CTA guidance](https://www.pixpa.com/blog/how-to-optimize-the-hero-section-of-your-portfolio-website) | Each view has one filled accent action ("Play featured episode" in the hero, "Discuss a project" in the header). Secondary buttons are outlined, with a clearer `--line-strong` border and a hover state. |
| 9 | Make targets at least 24×24 CSS px (AA); this site targets 44 px. | [WCAG 2.2 SC 2.5.8 Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | This was already the case and is now tested. Every nav link, button, and filter is at least 44 px tall, and the new E2E checks nav targets on every viewport. |
| 10 | Give text at least 4.5:1 contrast (AA). | [WCAG 2.2 SC 1.4.3 Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) | A unit test computes contrast for text, muted text, accent, and the highlighted nav state in both themes. Nav links reach at least 7:1 (AAA). |
| 11 | Give component boundaries at least 3:1 non-text contrast. | [WCAG 2.2 SC 1.4.11 Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) | A new `--line-strong` token (3:1 or better on the canvas in both themes) is used for secondary buttons, filters, and social icons. Decorative dividers keep `--line`. |
| 12 | Keep keyboard focus visible. | [WCAG 2.2 SC 2.4.7 Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html); [MDN `:focus-visible`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/:focus-visible) | This was already the case: a 3 px `--focus` outline. The new E2E confirms it on keyboard focus of the nav. |
| 13 | Keep line length readable, around 50–75 characters. | [Baymard, Optimal Line Length](https://baymard.com/blog/line-length-readability) | A new `--measure: 62ch` token caps hero, contact, and About paragraphs. |
| 14 | Use fluid typography with `clamp()` and rem bounds, so zoom and user font settings still work. | [MDN `clamp()`](https://developer.mozilla.org/en-US/docs/Web/CSS/clamp); [WCAG 2.2 SC 1.4.10 Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) | The name, role, tagline, copy, spacing, and grid gaps use `clamp()` with rem bounds. Body text moved from `16px` to `1rem`. |
| 15 | Design for large, high-resolution screens: widen the canvas and scale type proportionally, without stretching text lines. | [Launchpad, fluid typography with clamp() and large displays](https://launchpad-design.co.uk/fluid-typography-css-clamp-uk-frontend-developers/); [LADS Media, layout widths](https://ladsmedia.com/the-best-screen-layout-width-for-modern-websites/) | The container grows from 80 rem to 100 rem from 1680 px up. The root size scales to 112.5%, 125%, and 150% at 1920, 2400, and 3200 px, and is set in % so user settings still apply. Nav text is 17 px at 1440, 21 px at 2560, and 25.5 px at 3840. |
| 16 | Reflow down to 320 px with no horizontal scroll. | [WCAG 2.2 SC 1.4.10 Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) | E2E asserts no horizontal overflow at 390, 768, 1440, 2560, and 3840 px, and the existing phone test also covers 320 px. |
| 17 | Group related content by proximity and use a consistent spacing rhythm. | [NN/g, Visual Hierarchy (grouping)](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/) | New spacing tokens: `--space-section`, `--space-tight`, `--gap-grid`. The thin timeline strip uses the tighter rhythm. In Selected work, the lead edit takes a 2×2 slot when the count fills whole rows, and portrait edits are pillarboxed so rows line up with no empty cells. |
| 18 | Load the hero image fast (LCP): make it discoverable, give it high priority, and never lazy-load it. | [web.dev, Optimize LCP](https://web.dev/articles/optimize-lcp) | This was already the case: the hero poster has `fetchpriority="high"`, and only selected-work images load eagerly. |
| 19 | Reserve media dimensions to avoid layout shift (CLS). | [web.dev, Optimize CLS](https://web.dev/articles/optimize-cls) | Fixed a bug where the hero poster's HTML `height="675"` beat CSS `aspect-ratio`, which made the monitor almost square and very tall. It is now `height: auto` with a 16:9 aspect ratio. |
| 20 | Respect motion and theme preferences, and never autoplay. | [MDN `prefers-reduced-motion`](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion); [MDN `prefers-color-scheme`](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-color-scheme); [NN/g heuristic #3, User control and freedom](https://www.nngroup.com/articles/ten-usability-heuristics/) | The new hover transitions are covered by the existing reduced-motion override, which the E2E checks. The persistent dark/light toggle stays, dark remains the default, and there is still no autoplay. |

## How this was verified

- Unit contracts: `scripts/issue-39-ui.test.mjs` covers hero identity, nav prominence, high-resolution scaling, contrast math, and nav-spy behavior. The existing contracts still pass.
- Browser acceptance: `tests/portfolio.e2e.spec.mjs` runs the issue-39 tests at 390×844, 768×1024, 1440×900, 2560×1440, and 3840×2160 in both themes. They cover hero content, whether the name is above the fold, nav size, contrast and target size, no horizontal overflow, no hero dead space, a 16:9 monitor, the current-section indicator, focus visibility, reduced motion, and whether Selected work leaves empty gaps.
